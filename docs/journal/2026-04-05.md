# 이벤트 날씨 위치 추정 계획 

사용자가 법정동 이름을 작성해서 넣었다면,
해당 법정동 위치를 제공.
사용자가 입력한 장소를 기반으로 확인된 법정동 주소를 
이벤트 카드에 같이 출력.
중복 법정동으로 인해 엉뚱한 법정동이 나오면, 사용자에게 법정동 상위 주소 입력을 유도.
장소 옆에 안내 툴팁 제공.

우려하는 점.
사용자가 법정동을 우리 법정동 주소 테이블에 맞게 쓸 가능성은 없다.
차라리 법정동을 입력하는 UX를 제공하면 어떨까?
현재 위치로 날씨가 제공됩니다. 표시를 누르면,
우리 장소 선택하는 UX를 제공하고, 그 UX에서 법정동을 선택하게 하는거지.
그리고 선택하면, 입력에 법정동 정보를 [] 괄호 안에 넣어서 저장하고.
[] 괄호 안에 저장된 법정동 기반으로 날씨를 가져온다.

좌표정보를 BASE64로 인코딩하여 저장. 헤더로 TODAY_AIR_B53A8
0GI 라는 헤더로 저장할까?
아냐 다른 캘린더에서 보면 쓰레기 데이터로 보여.

차라리 아래와 같은 규칙으로 하자.

1. 이벤트의 장소이름으로 아래의 순서로 법정동을 가져옴.
   1. [] 태그 안에 있는 법정동 이름 검색
   2. 장소에 있는 이름을 띄어씌기로 단위로 법정동 탐색
   3. 현재 위치
2. 이벤트 카드에 유추된 법정동을 []에 넣어서 표시.
3. 유추 실패시, [현재 위치] 표시.
4. UX로 표시된 [] 주소를 클릭하여 사용자가 직접 [법정동]을 선택할 수 있는 UX제공.
5. 사용자에 의해 선택된 법정동을 이벤트의 장소 필드에 [] 안에 넣어서 저장.
   1. 장소 필드에 [] 괄호가 있을 경우. 
      1. 사용자에게 동의후 진행.
         1. 동의시. 기존 [] 안에 덮어씀.
         2. 미 동의시. 이벤트에 법정동을 저장하지 않음.
   2. 장소 필드에 [] 괄호가 없을 경우.
      1. 선택된 법정동 정보를 저장.
